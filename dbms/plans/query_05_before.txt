Query 05 — Project-level scan statistics

Project UUID: 01180456-4514-4170-b1dd-ed9affba07ee

Benchmark query:
EXPLAIN (ANALYZE, BUFFERS, VERBOSE)
SELECT
    p.id,
    p.name,
    COUNT(DISTINCT s.id) AS total_scans,
    COUNT(DISTINCT f.id) AS total_findings,
    COUNT(DISTINCT s.id) FILTER (
        WHERE s.status = 'COMPLETED'
    ) AS completed_scans
FROM projects p
LEFT JOIN scans s ON s.project_id = p.id
LEFT JOIN findings f ON f.scan_id = s.id
WHERE p.id = '01180456-4514-4170-b1dd-ed9affba07ee'
GROUP BY p.id, p.name;

Plan observations:
- projects_pkey Index Scan finds the selected project.
- scans uses a Sequential Scan and removes 49,990 rows by filter.
- findings uses Bitmap Index Scan on idx_findings_scan_id and Bitmap Heap Scan.
- PostgreSQL sorts the joined rows and uses GroupAggregate.
- IMPORTANT: idx_findings_scan_id is still present and used in these supplied plans. These are the user's measured BEFORE plans, but not a fully index-free baseline.
