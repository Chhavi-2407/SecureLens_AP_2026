
QUERY 02 — BEFORE INDEX OPTIMIZATION
Project Scan History

Database: securelens_benchmark
Table: scans
Total scans: 50,000
Target project: Project 1

Query:
EXPLAIN (ANALYZE, BUFFERS, VERBOSE)
SELECT
    id,
    project_id,
    status,
    language,
    security_score,
    started_at,
    completed_at,
    created_at
FROM scans
WHERE project_id = (
    SELECT id
    FROM projects
    WHERE name = 'Project 1'
)
ORDER BY created_at DESC;

ANALYSIS

The query performs sequential scans on both the
projects and scans tables.

PostgreSQL examines all 5,000 projects to locate
Project 1 and examines all 50,000 scan records
to retrieve the matching scans.

Only 10 scan records match the requested project.
The remaining 49,990 records are removed by the filter.

The matching records are sorted by created_at in
descending order using quicksort.

The execution plan indicates that additional indexes
on the project lookup and scan filtering/sorting
columns may improve query performance.

This is the baseline result before adding the
proposed optimization indexes.
